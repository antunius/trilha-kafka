Broker, cluster, controller

O que é. Broker = um processo JVM (no lab: o container kafka) que guarda partições, aceita Produce/Fetch e replica. Você não fala com “o Kafka”: o cliente resolve o líder de cada partição via metadata e manda bytes para bootstrap.servers (depois para o líder certo). Cluster = N brokers com o mesmo cluster.id. Controller = o broker eleito que cria tópico, elege líder, trata falha. Em cluster novo isso é KRaft (quorum dentro do Kafka). ZooKeeper é o desenho antigo.

Analogia: broker = funcionário com um arquivo; cluster = a equipe; controller = quem decide quem guarda o quê se alguém falta.

Na prática. O Compose sobe um broker KRaft e anuncia dois listeners: um para os containers (kafka:29092), outro para a sua máquina (localhost:9092).

spring.kafka.bootstrap-servers: localhost:9092

No lab. labs/kafka/docker-compose.yml — serviço kafka, KAFKA_PROCESS_ROLES: broker,controller.
