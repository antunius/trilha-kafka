Tópico

O que é. Um tópico é um nome no cluster que aponta para um conjunto de logs (as partições). Não é um processo, não é uma fila na memória do broker. Metadata do tópico (quantas partições, fator de réplica, configs de retenção) fica no controller. Os bytes das mensagens ficam nos arquivos das partições, nos discos dos brokers líderes/followers. Append-only: ninguém reescreve a linha 40. Quem “apaga” é retenção ou compaction, em segmentos velhos.

Analogia: o nome da página do caderno. “Pedidos criados”, não “caixa do João”.

Consumidores se inscrevem no tópico, não no produtor. O tópico é o contrato. Nomeie pelo fato (pedidos.criados), não pelo destinatário (fila-do-faturamento).

Na prática. Criar o tópico do lab com 3 partições:

docker compose exec kafka /opt/kafka/bin/kafka-topics.sh \
  --bootstrap-server localhost:9092 \
  --create --if-not-exists \
  --topic pedidos.criados \
  --partitions 3 \
  --replication-factor 1

No lab. O Spring faz o mesmo no boot: labs/kafka/pedido-service/.../TopicConfig.java (TopicBuilder.name(...).partitions(3)).

Auto-create de tópico em produção esconde o contrato: alguém publica e o cluster inventa 1 partição. No Compose do lab isso está KAFKA_AUTO_CREATE_TOPICS_ENABLE=false de propósito.
