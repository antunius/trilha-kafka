Segmento, retenção e compaction

O que é. O log da partição não é um arquivo eterno: é uma fila de segmentos (00000000000000000000.log, depois outro quando atinge segment.bytes). Retenção (retention.ms / retention.bytes) apaga segmentos fechados que passaram do prazo. Quem não commitou a tempo perdeu a linha (a menos que tenha copiado para outro lugar). Compaction (cleanup.policy=compact): para cada key, o cleaner mantém o value mais recente; tombstone (value nulo) pede para apagar a key. Serve changelog/CDC, não filme completo.

Analogia: o caderno é cortado em cadernos menores. Os velhos vão para o lixo — ou, na compaction, fica a última versão de cada pessoa.

Na prática. Ver configs do tópico (incluindo retenção padrão do broker):

docker compose exec kafka /opt/kafka/bin/kafka-configs.sh \
  --bootstrap-server localhost:9092 \
  --entity-type topics --entity-name pedidos.criados --describe

No lab. O tópico didático usa retenção padrão do Apache Kafka na imagem. Não trate o lab como backup.

Kafka não é S3. Sem retenção infinita (cara e rara), o log esquece. Compaction não te devolve os estados intermediários. Tombstone não é DELETE no Postgres.
